# AI Prompt 与问题解决记录

开发过程中使用 Codex 辅助实现、测试构建和文档整理。核心 Runtime 未使用现成 Agent 框架。以下提示为开发约束的归纳，非逐字会话转录。

## 主要提示与用途

| 提示摘要 | 用途与落地 |
| --- | --- |
| 使用 Python 实现最小 Agent，主循环自行编写，控制模块数量 | 拆分 Runtime、模型适配器、工具注册表、SQLite 存储和上下文组装 |
| 真实模型基于名称、描述与 JSON Schema 选择工具；mock 与真实路径分开 | 原生 Chat Completions function calling；独立 MockModel 用于离线演示 |
| 同用户不同窗口相互隔离，关闭后可恢复 | 以 `(user, sid)` 作为会话范围，持久保存消息和待办 |
| 对参数错误、工具失败、模型异常和循环上限构造测试 | 使用 ScriptModel、临时 SQLite 和本地 HTTP 服务测试异常分支 |
| 压缩旧对话时保留工具调用与结果配对，不删除原始历史 | 按完整旧轮次摘录，保存摘要水位，超出单轮预算则明确停止 |
| 检查并发与崩溃后是否会重复执行写操作 | 原子租约、owner 校验、call_id 去重，以及中断结果补齐 |

运行时 system prompt 保存在 `agent/context.py` 的 `SYSTEM` 中；工具描述和参数 Schema 保存在 `agent/tools.py`，可随代码版本复现。

## 问题解决记录

| 问题 | 处理 | 验证 |
| --- | --- | --- |
| 模型可能返回坏 JSON、缺失参数或未知工具 | JSON 解码与 Schema 校验分层，错误作为工具结果回填 | 坏参数纠正、类型错误、额外字段、未知工具用例 |
| 畸形响应 `message=[]` 原先触发 AttributeError | 先用测试复现，再显式检查 message 为对象，统一转换为 ModelError | 畸形响应解析用例 |
| 两个执行器可能同时使用同一会话历史 | SQLite 条件更新原子抢租约，写状态前检查 owner 和有效期 | 同时抢占与过期 owner 用例 |
| 待办已落库但工具结果尚未保存时进程中断 | 对同 call_id 的新增去重，恢复时补未知结果，不自动重放写操作 | 崩溃恢复和同 ID 去重用例 |
| 逐条截断历史会破坏工具协议 | 按完整旧轮次压缩，原始消息保留在 SQLite | 调用结果配对与 200 轮对话用例 |
| 长工具结果可能突破上下文预算 | 用带 truncated 标记的有效 JSON 包装预览 | 长结果可解析且长度受限用例 |
| 工具或 HTTP 错误可能暴露内部信息 | 内部工具异常统一脱敏，HTTP 错误只报告状态码，禁止请求重定向 | 异常脱敏、HTTP 错误与重定向用例 |
| Windows 输出捕获出现中文乱码 | 对同一数据使用 UTF-8 模式重跑，运行命令采用 `python -X utf8` | 中文待办输出正常 |

## 验证结果与限制

31 个本地自动测试通过；另验证了 CLI 计算、跨进程工具追问、待办持久化及会话隔离。完整结果见 [测试报告](TEST_REPORT.md)。

HTTP 适配器通过本地服务验证；未使用真实供应商模型进行端到端推理测试。历史摘录为有损压缩，同 call_id 去重也不等于跨系统的 exactly-once。上述限制保留在设计说明中。
